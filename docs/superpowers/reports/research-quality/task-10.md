# Task 10 report: deterministic research reports and logs

Added pure `render_report(snapshot)` and `render_log(snapshot)`. Reports keep the exact question and goal, separate investigation and answer statuses, retain a useful Draft for incomplete/budget-exhausted runs, and qualify source status and mathematical scope. They show claim findings, cited passages and offsets, approaches, actual challenges and revisions, complete tool receipt inputs/results/scopes, source origin and dates, provenance hashes, provider observations, counters, time, bytes, available token totals, unknown costs, and the formal-verification limitation.

Untrusted question, goal, answer, citation, challenge, and error text is rendered inside dynamically sized code fences or blockquotes so embedded Markdown cannot add coordinator status headings. “Open” status is only reported when provenance is valid and the current audit explains a cited critical source assertion as open; it is explicitly scoped to supplied/captured sources. The log lists chronological routing reasons, dependencies, outcomes, elapsed milliseconds, and errors, without worker reasoning transcripts. Rendering uses no provider or filesystem calls and is deterministic for a fixed snapshot.

The event projection now retains each action outcome and telemetry plus the terminal event time in `ResearchSnapshot`, enabling deterministic disclosure and wall-time calculations after replay.
