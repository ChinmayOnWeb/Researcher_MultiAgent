# Task 7 report: deterministic routing and qualified assessment

Added `next_decision(snapshot)` as a pure ordered router, plus deterministic `assess` and `assess_latest`. The assessment distinguishes mechanical provenance from model-reviewed semantics, propagates claim dependency uncertainty, rejects invalid evidence, treats missing critical challenges and proof-step coverage as inconclusive, and lets a bound failed tool challenge refute a claim despite a positive audit check. An unrelated receipt cannot overturn a claim. Quick finishes after its one answer as unverified; Deep and Research require synthesis and a fresh audit of the current Draft.

The router handles terminal, ambiguous, human-wait, and failed-action states before selecting work. It orders Frame, gates, authorized URL capture, bounded checks, branches, synthesis, audit, repair work, and qualified finish. Tool deduplication uses operation plus canonical arguments while excluding proposal ID. It observes capability/call/repair/branch caps, reserves calls for re-audit and third-branch follow-up, does not reuse stale audits, and never starts branch c in Deep. Gate-added source descriptors and text evidence are projected by replay so routing and worker packets can see the exact authorized inputs.

During integration, event replay and storage were corrected to persist complete broker ToolReceipts rather than bare operation results. Replay now revalidates receipts against the intended coordinator Action, populates captured source and tool catalogs, and derives latest Draft/Audit IDs. The broker implementation version also resolves through the trusted manifest added for the Astra §8.1/§8.2 ruling.
